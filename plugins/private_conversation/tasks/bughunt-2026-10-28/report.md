## Unconfirmed reflection candidate

**P2 candidate: early ACK capacity is below supported reply length.** PCV supports up to 24 reply segments, but retains only eight distinct fresh pre-registration ACK receipts. If a supported 13-segment reply's final ACK is refused by the receipt cap before registration, later registration reconciles only the final ID and can return `registration_missing` while the record remains registered. The inspected path schedules no retry for `receipt_busy`. This could lose the optional opinion evaluation; it does not establish a failure to play speech.

The source composition is documented in [the reflection review](reflection/report.md). The exact integrated fixture could not reach that assertion on the permitted Windows PHP runtime: real receipt-file permission checks rejected Windows mode `100666` after `chmod(0600)`. The raw failures are retained, not counted as product failures or passing evidence. A filesystem with genuine Unix private-mode semantics is needed for the smallest decisive fixture: park 13 valid distinct ACK tuples before registration, invoke actual registration/drain, and inspect the final receipt, registry status and evaluator calls. No test-server window was requested or used. Natural CHIM/client occurrence and any external ACK retry remain unverified.
