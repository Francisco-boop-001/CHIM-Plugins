## Candidate: early ACK capacity can strand a supported full reply

**Severity: P2 candidate; owner: PCV.** In an active Solo reflection, 13 distinct, valid `_speech` ACKs for one actor/config/generation can arrive before postrequest registers that reply. PCV’s supported full-reply cap is 24 (PCV `server/reflection.php:14–23`, MP `server/store.php:9–10`); the retained fixture records a historical 10–13-line observation, not a fresh 0.1.24 occurrence (`tests/reflection_reply_length_check.php:4–6`).

The path is concrete in source. `_speech` requests enter PCV through `server/prerequest.php:12–28`. `pcvReflectionEvaluateAck()` routes unmatched ACKs to `pcv_reflection_store_ack_receipt()` (`server/reflection.php:142–166`). That helper retains up to eight fresh matching receipts, then returns `busy` without eviction (`server/reflection_receipt.php:4–7, 281–301`). The caller logs `receipt_busy` as `reflection.ack_skipped` and returns before queuing shutdown reconciliation (`server/reflection.php:143–166`).

After generation, `server/prepostrequest.php:78–90` calls `pcvReflectionRegisterLastOutput()`. Registration can group all proven lines (`server/reflection.php:849–857; 377–447`) and then attempts to reconcile the exact final utterance (`server/reflection.php:919–923`). That drain searches only for the registered final ID: absence returns `registration_missing` (`server/reflection.php:926–949, 961–988`). Thus, if the 13th/final ACK was one of the over-capacity receipts, the record can remain `registered` with a 13-line registration but no final receipt; the native ACK reader and evaluator are not reached. Existing evaluation requires a matching registered final ACK (`server/reflection.php:1000–1103`). This is a missed NPC-opinion evaluation, not evidence that the spoken response failed or audio was not played.

The “older ACK” short-circuit at `server/reflection.php:129–140` does not cover a new reply whose event IDs are newer than a previous registration: `pcv_reflection_ack_predates_registration()` skips only when the source event ID is less than the old final event ID (`server/reflection.php:348–359`). The existing `tests/reflection_reply_length_check.php:43–56` deliberately keeps a newer ACK on the receipt path. A repeated final `_speech` arriving after registration could use the direct-ACK branch (`server/reflection.php:100–126`), but the inspected PCV path does not schedule a retry when capacity returns `busy`. No evidence here establishes whether CHIM or the client automatically repeats such an ACK.
