One boundary is worth keeping explicit: `evidence_unavailable` is selected for the reader's `error`/exception path. A missing close report is deliberately returned as `error = false` (“absence, not an error”) by the current reader contract and fixture ([server/state.php:1370](../../server/state.php#L1370), [tests/scene_resilience_check.php:50](../../tests/scene_resilience_check.php#L50)). Likewise a missing/stale wide report is represented in `missing` as `wide_unavailable`, without promoting the overall `error` flag ([server/state.php:1300](../../server/state.php#L1300), [server/state.php:1447](../../server/state.php#L1447)). Those cases can therefore end as `members_gone`. This matches the current source/test contract; if product semantics intend missing or stale reports to mean “unknown,” that requires a separate explicit change and regression case, not an inference from this patch.
