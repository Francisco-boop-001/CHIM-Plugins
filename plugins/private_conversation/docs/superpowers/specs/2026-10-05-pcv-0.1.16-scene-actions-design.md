# Private Conversation 0.1.16: actions inside scenes (draft)

**Date:** 2026-10-05.
**Status:** draft; awaiting the user's answers to the open questions.
**Scope:** the user reopened PCV's closed feature scope for this one feature: "Reopen it for this, start with the action lists". Motivation: a character drinking alone while reflecting should be able to drink, and an argument should be able to end in a brawl.

## Facts gathered (E: test clone, read-only; the live D: CHIM may be newer, so re-check look-only before building)

- **CHIM core actions:** `functions/functions.php`, about 50, gated by `ENABLED_FUNCTIONS`. Relevant ones (English descriptions from `F_TRANSLATIONS_LOCAL`):
  - **Drink:** "Drinks a beverage to quench thirst or enjoy flavor."
  - **Toast:** "Raises a glass in celebration or honor."
  - **Consume:** "…consumes a food, drink, or potion from inventory. Use the exact BaseID:ItemName inventory identifier in the target field."
  - **TakeASeat** and **Relax**.
  - **Brawl:** "starts a brawl with #PLAYER_NAME# or another nearby NPC: an agreed, bare-fisted fight that is not meant to kill…"
  - **Surrender**.
  - **Attack:** "with intention to kill".
  - **KillTarget:** "Kill a chosen NPC, actor, or #PLAYER_NAME# immediately."
  - Others: movement, gifts, crime, spawning, teleport, director, `EndConversation`.
- **SHARMAT** (`ext/aiagent_nsfw/functions.php`) registers its own actions:
  - `ExtCmdHug`, `ExtCmdHoldHands`, `ExtCmdKiss`;
  - `ExtCmdRemoveClothes`, `ExtCmdPutOnClothes`;
  - `ExtCmdStartSex` and variants, `ExtCmdStartMassage`, `ExtCmdStartSelfMasturbation`;
  - `ExtCmdAcceptSex`, `ExtCmdRefuseSex`;
  - role-specific `ExtCmdQuitProstitution`, `ExtCmdGiveFreeService`, `ExtCmdWorshipMaster`, `ExtCmdAskForFreedom`.

  SHARMAT's own context_pre gates `ENABLED_FUNCTIONS` per NPC (relationship type, consent, minors and other rules), and it runs before PCV's context_pre.
- **SHARMAT counts drinking only from `Consume` of a real alcoholic inventory item** (consume-only mode). `Drink` and `Toast` are social flavour and do not raise the drunk stage.
- **The reply format's `action` field is an enum of `FUNC_LIST`.** `target` and `item` are free text, and `Consume` puts the item id in `target`, so `target` cannot be constrained to actors by an enum.
- **CHIM's post-filter.** After the reply completes and before the actions are sent, CHIM runs every function in `$GLOBALS["action_post_process_fnct_ex"]` over the action list (`lib/data_functions.php` about line 6223, "ACTION POST-FILTER"). Actions are `Name|command|Action@parameter` strings.
- **PCV today** (context_pre.php) sets `FUNCTIONS_ARE_ENABLED=false` and refuses the request unless `FUNC_LIST` is `[]` or `['Talk']`.

## Proposal

**Three opt-in groups**, per scene, off by default (page checkboxes):

| Group | Allowed actions | Target rule |
| --- | --- | --- |
| Personal | Drink, Toast, Consume, TakeASeat, Relax | self or an item only; never another actor |
| Physical | Brawl, Surrender | Brawl target must be a scene member (never the player or a bystander) |
| Intimate (SHARMAT) | the SHARMAT `ExtCmd*` actions that SHARMAT itself left enabled for this speaker | the target must be a scene member |

**Never allowed in scenes:** Attack, KillTarget, movement or travel, gifts and gold, crime and bounty, spawning, teleport, Director, MakeFollower, EndConversation.

**Enforcement:**
1. **Before generation:** `ENABLED_FUNCTIONS` / `FUNC_LIST` becomes the intersection of what CHIM/SHARMAT already enabled and the scene's allowed groups. PCV only ever removes; it never re-enables something SHARMAT gated off.
2. **Prompt:** one line naming the allowed targets (the members).
3. **After generation:** a PCV filter in `action_post_process_fnct_ex` drops any action whose name is outside the allowed groups, or whose actor target (after resolving "Name [RefID: …]") is not a scene member, or is the player while the player is excluded. Drops are logged (`routing.action_dropped`, with reason).
4. **context_pre safety check** changes from "Talk only" to "only allowed actions".

**Solo:** only the Personal group; a reflecting NPC can drink alone.

**Wrap-up and solo sentinel turns:** actions follow the same groups. The listener sentinel is unaffected.

## Decisions (the user, 2026-10-05)

1. **"brawl adds drama":** Brawl is in; Attack and KillTarget stay out of scenes entirely.
2. **Intimacy is in.**
   - Pairs and groups: tender scenes between members (for example a married couple travelling with the PC, player excluded; no one outside the scene can be drawn in).
   - Solo: self-directed moments ("those happen in real life").
   - SHARMAT's consent and safety gating still decides what is enabled; PCV only narrows.
3. **"Your best choice":** the groups are stored with the scene like the scene card. Re-arming keeps them; END resets them to off, so a new scene never inherits intimacy by surprise.

## Implementation details fixed after reading the code

- **Action strings:** the post-filter sees `Speaker|command|Code@parameter`. The parameter is either plain text or JSON with `target`. `ExtCmdStartThreesome` lists partners comma-separated. `Consume` puts the item id (`BaseID:ItemName`) in `target`.
- **Intimate list (SHARMAT 3.1.9.3; it may need updating when SHARMAT changes):** ExtCmdHug, ExtCmdHoldHands, ExtCmdKiss, ExtCmdRemoveClothes, ExtCmdPutOnClothes, ExtCmdStartSex, ExtCmdStartBlowJob, ExtCmdStartAnalSex, ExtCmdStartMassage, ExtCmdStartThreesome, ExtCmdStartHandJobSex, ExtCmdStartTitfuck, ExtCmdDrinkBloodSex, ExtCmdStartSelfMasturbation, ExtCmdAcceptSex, ExtCmdRefuseSex.
  - SHARMAT's role actions (prostitution, worship, freedom) are excluded.
- **Solo:** Personal plus Intimate, with targets only empty or the reflecting NPC (self).
- **Player included:** the player counts as a member for targets.
- **Brawl prompt:** its "available targets" (`FUNCTION_PARM_INSPECT`) are narrowed to the members.
- **SHARMAT target coercion:** SHARMAT coerces some AcceptSex targets to the player. PCV's post-filter is registered later, so it sees the final target and drops it when the player is excluded.
