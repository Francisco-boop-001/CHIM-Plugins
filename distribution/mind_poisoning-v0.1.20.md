# Mind Poisoning v0.1.20 — PRE-ALPHA

Version 0.1.20 is a PRE-ALPHA development-candidate release. It adds conservative optional relationship-type judgments alongside the existing affinity judgment and fixes standalone dashboard normalization for canonical Player affinity by loading the CHIM relationship helper from the validated server root; the isolated fixture used the pinned core helper. Both additions passed isolated fixture checks; the new type behavior has no live database, provider, or gameplay verification.

## Conservative single relationship type

The optional `type_change` uses the existing model call and eligibility gates for ordinary NPC gossip, Player-origin input, NPC acknowledgements and overhearing, and registered solo reflection. Legacy affinity-only responses remain accepted. The default is to keep the current type, and a change needs clear lasting grounds and exact evidence. The feature uses one native CHIM relationship type at a time; simultaneous labels and Skyrim vanilla relationship ranks are not supported.

Current custom types are preserved. Current `romantic`, `familial`, and `professional` types cannot be replaced by temporary types (`jealous`, `protective`, `suspicious`, `fearful`, `obsessed`, `awed`, `contempt`, `pitying`, `grateful`, `curious`, `dismissive`, or `admirer`). A valid protected proposal can preserve the type while an otherwise valid affinity change applies. Unknown or malformed types reject the response; a `from` value that differs from the captured snapshot invalidates it. If the actual type changes before the locked write, the whole judgment is stale and no affinity portion is applied. A type-only change with zero affinity delta is valid and persists with the edge, replay ledger, and history under the existing lock and transaction.

The reflection API version and function signatures remain unchanged. The version-1 ledger accepts the new optional judgment and decision fields while old entries remain readable; no migration or CHIM core change is required. `changed_count` counts distinct relationships changed by affinity or type, while `affinity_changed_count` and `type_changed_count` report each dimension. The existing affinity `changes` array keeps its fields. The dashboard separates proposed decisions, confirmed applied type changes, and the current type; proposals are not shown as application. Added type diagnostic fields contain only the subject, type tokens, and fixed decision reason when present; they do not add raw dialogue.

## Dashboard correction

The standalone dashboard loads the CHIM relationship helper from the validated server root when normalizing a canonical Player edge; the isolated fixture used the pinned core helper. A valid affinity is no longer displayed as `Invalid` because the required helper was absent. If the required helper is missing, the result is `Unavailable`; malformed relationship data remains `Invalid`. This correction was checked with isolated fixtures and does not establish a live database or browser deployment result.

## Private Conversation compatibility and verification limits

The Private Conversation revision-2 importer is unchanged. It classifies a confirmed type-only commit as committed because `changed_count` is positive and ignores the new type details; use Mind Poisoning's dashboard or filtered JSONL log to inspect them. Isolated integration checks confirmed that type-bearing Mind Poisoning records are accepted and classified by that importer. Its physical POSIX JSONL sink was not exercised on Windows. No PCV code or API version change is included. Prior affinity-path live observations do not verify the new type behavior.
