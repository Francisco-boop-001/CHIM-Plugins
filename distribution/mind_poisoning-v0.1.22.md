# Mind Poisoning v0.1.22 — BETA CANDIDATE

This release uses standard GitHub classification (`prerelease=false`) so a newer CHIM manager can discover `chim-plugin.tar.gz`. Its label remains **BETA CANDIDATE**; standard classification does not graduate it. Apparently a release switch can help a catalog find a package, but it cannot make the test report longer.

Mind Poisoning lets a listener revise their opinion of a named person after hearing praise, criticism, or a balanced account. The listener can disagree or make no change; gossip does not become shared world truth. The optional relationship-type change remains limited to one native CHIM type at a time, with custom and enduring `romantic`, `familial`, and `professional` types protected from temporary reactions.

## What changed

Version 0.1.22 narrowly prevents generic `Vampire` and `Black` words from becoming generated NPC aliases. Exact token matches are filtered through the existing generated-alias routes: first-word, phrase-before-`the`, and bracket-stripped candidates. The fix does not remove exact catalog names such as `Vampire Fledgling` or `Black Widow`, nor literal mononyms such as `Black`, `Guard`, or `King`. Normal names, Unicode, possessives, and alias collisions remain covered by focused checks. Common exact word names such as `May` and `Guard` can still depend on model judgment.

This addresses one observed wrong-subject path. It does not add pronoun resolution, taxonomy, prompt changes, schema changes, or a general entity-resolution system. The installed 0.1.21 observation remains a valid historical finding; installed 0.1.22 behavior is not established.

## Duplicate-install recovery

When both Mind Poisoning extension copies are present, CHIM's current bootstrap stops all CHIM conversation requests until one copy is removed. If both `ext/mind_poisoning` and `ext/CHIM-MindPoisoning` exist, back up first and follow the route-specific steps below. Removing extension code does not erase affinity, ledger, or history stored in CHIM's database.

1. **Choose one route to keep.** Do not load a save while MO2 sync might recreate a server folder.
2. **Stop resync temporarily.** Disable or remove the MO2 sync source while cleaning up. This prevents recreation; it does not uninstall an existing server copy.
3. **Back up database and configuration.** Preserve the CHIM PostgreSQL database and relevant server/plugin configuration. Do not drop relationship, ledger, or history data. If keeping a rollback copy, move it outside `HerikaServer/ext`; renaming it inside `ext` still leaves it eligible for recursive loading.
4. **For the Plugin Manager route:** if both standard folders exist, keep/update `ext/CHIM-MindPoisoning` and remove `ext/mind_poisoning` after the backup. If a single `ext/mind_poisoning` folder remains from a 0.1.14-or-newer Manager install, keep it in place; do not rename it. For 0.1.13 or older, use the [version-specific migration guide](https://github.com/Francisco-boop-001/CHIM-MindPoisoning/blob/mind_poisoning-v0.1.22/docs/deployment-migration.md#mind-poisoning-migration-from-0113-or-older) first.
5. **For the MO2 route:** keep the DWPkg-synced `ext/mind_poisoning` copy and remove the Manager-only `ext/CHIM-MindPoisoning` copy after the backup. Re-enable only the MO2 source you intend to use, update the ZIP with **Replace**, not **Merge**, and do not click Mind Poisoning **Install/Update** in the web Plugin Manager.
6. **Verify before resuming.** Confirm exactly one of `ext/mind_poisoning` or `ext/CHIM-MindPoisoning` remains before loading a save or restarting game requests. Database relationships and history remain after removing extension code.

See the [deployment and migration guide](https://github.com/Francisco-boop-001/CHIM-MindPoisoning/blob/mind_poisoning-v0.1.22/docs/deployment-migration.md) for the source context and full recovery procedure.

### 0.1.13-or-older Manager migration

For a legacy 0.1.13-or-older installation, there are two supported routes to the Plugin Manager:

- **Switch directly:** back up the PostgreSQL database and server/plugin configuration, disable or remove MO2 sync so it cannot recreate the old folder, then remove the old `HerikaServer/ext/mind_poisoning` code folder before installing through the Manager. Keep any rollback copy outside `HerikaServer/ext`. Do not clear database tables; stored affinity, ledger, and history remain.
- **Use the bridge first:** upgrade through the old CHIM-Plugins route to 0.1.14 or newer. That bridge records the canonical `CHIM-MindPoisoning` repository, so a later Manager update can reuse the matching extension folder.

Choose one route, not both. For MO2 file sync, keep that route and do not use the Manager's Mind Poisoning Install/Update controls.
