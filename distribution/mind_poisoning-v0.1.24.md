# Mind Poisoning v0.1.24 — BETA CANDIDATE

This candidate keeps standard GitHub release classification (`prerelease=false`) so a newer CHIM manager can discover `chim-plugin.tar.gz`. Its maturity remains **BETA CANDIDATE**; discovery is not graduation. This update explains one safety stop more clearly. The llama has not negotiated with the database.

## What changed

The dashboard now explains `restore-policy` in both **Interactions** and **Logs**; the player guide maps the same reason to its troubleshooting steps. Check the recorded **Outcome**, `stage`, and `model_outcome` together. A preflight `not_called` result means MP stopped before model work. The same reason can come from the persistence backstop after model work, so the recorded stage and outcome matter.

The reason describes the policy at that event, not the current setting or where it is configured. The guard remains in place: CHIM can retain newer relationship values while restoring older Mind Poisoning processing history (the deduplication ledger), risking a repeated effect. Changing a provider key or reinstalling will not resolve this reason. Ask the CHIM administrator to review the build and policy intent. Leave an intentional safety policy in place; change a setting only after reviewing CHIM’s broader restore behavior and backing up the database and configuration. Do not toggle it blindly.

This is display and documentation clarification. Evaluator behavior, APIs, guards, schema, reason codes, the filtered JSONL download, and its filters are unchanged. The raw filtered records remain available; explanatory text does not rewrite them. A controlled request after an administrator-approved policy change may call a provider, but does not guarantee a nonzero change or passage through every later gate. A zero change or another skip can be legitimate.

The dashboard renderer, PHP syntax, manifest-update, site-compatibility, and all eight packaging checks passed for the staged 0.1.24 source; all four candidate installer assets were built and verified locally. The PHP fixtures used standalone Windows PHP with `-n`, `mbstring`, and `pgsql` and made no network, database, or provider calls. See the [verification summary](../docs/verification-v0.1.24.md) and the [candidate evidence](../docs/beta-candidate-evidence.md). The prior 0.1.23 focused checks and 0.1.20 B1/B3 campaigns retain their historical scope; they do not verify the 0.1.24 candidate. Staged-source checks do not establish a clean-tag rebuild or downloaded-asset byte equality; those are separate publication gates. These checks also do not establish installed CHIM behavior, provider behavior, live database persistence, or gameplay.

## Choose one installation route

- **MO2:** use the recommended plain [MO2 ZIP](https://github.com/Francisco-boop-001/CHIM-MindPoisoning/releases/download/mind_poisoning-v0.1.24/mind_poisoning-0.1.24-mo2.zip). Keep one enabled Mind Poisoning version. Update with **Replace**, not **Merge**; the ZIP contains its matching DWPkg.
- **Experimental CHIM topic discovery:** in a CHIM build whose Plugin Manager supports the `chim-plugin` topic, use **Refresh Plugins → Mind Poisoning → Install/Update** and confirm `mind_poisoning-v0.1.24`. The manager downloads the flat [`chim-plugin.tar.gz`](https://github.com/Francisco-boop-001/CHIM-MindPoisoning/releases/download/mind_poisoning-v0.1.24/chim-plugin.tar.gz); do not upload it manually. This route requires standard GitHub release classification and a newer manager than pinned core `cf5030f`; a complete 0.1.24 install through it is not established.
- **Existing explicit manifest/channel install:** use [`mind_poisoning.tar.gz`](https://github.com/Francisco-boop-001/CHIM-MindPoisoning/releases/download/mind_poisoning-v0.1.24/mind_poisoning.tar.gz).
