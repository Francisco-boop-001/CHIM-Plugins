# Mind Poisoning v0.1.23 — BETA CANDIDATE

This release uses standard GitHub classification (`prerelease=false`) so a newer CHIM manager can discover `chim-plugin.tar.gz`. Its label remains **BETA CANDIDATE**; catalog visibility is not a graduation. We added context, not clairvoyance. The llama is still not certified to read anyone's mind.

## What changed

The evaluator can now receive the opinion owner's existing relationship context about the named subject: `relation`, `note`, `best`, and `worst`. Each valid nonempty string is capped at 160 UTF-8 bytes. The bounded fields are available to ordinary speech, actor-owned reflection, and enabled NPC ACK overhearing. Bad optional fields are omitted independently. No extra model call, new relationship label, agreement state, or schema is added.

These are untrusted notes, not proof of what happened. They can be old, incomplete, truncated, or describe only one person's feelings and expectations. Attraction does not establish reciprocal feelings, exclusivity, or a mutual commitment. The evaluator may use the context, ignore it, or still make no change. Existing type safeguards remain in force.

The focused isolated PHP checks cover the context projection and existing relationship-type, influence, reflection, and overhearing paths. They do not verify provider behavior, live database persistence, an installed 0.1.23 package, or Skyrim gameplay. See the [candidate evidence](../docs/beta-candidate-evidence.md) and [verification summary](../docs/verification-v0.1.23.md).

## Duplicate-install recovery

A clean install through one route creates one extension copy. After any install or route change, verify that exactly one of `ext/mind_poisoning` or `ext/CHIM-MindPoisoning` exists. Keep exactly one enabled MO2 package version. Two installed copies stop all CHIM conversation requests until one is removed. In an auditor's 0.1.21/0.1.21 reproduction, `main.php` globals boot failed with `Cannot redeclare ChimMindPoisoning\mindPoisoningEvaluateReflection`; the web Plugin Manager remained available.

If both folders exist, stop game loading and back up the database and server/plugin configuration first. Disable the MO2 sync source while cleaning up; this prevents resync but does not remove a server copy. If keeping a rollback copy, store it outside `HerikaServer/ext`; renaming it inside `ext` does not disable recursive loading.

- **Keep the MO2 route:** disable MO2 sync, remove `ext/CHIM-MindPoisoning`, and keep the MO2-managed `ext/mind_poisoning` copy. Re-enable only the intended MO2 source after the folders are resolved; use **Replace**, not **Merge**, for updates. Do not use the web Plugin Manager's Mind Poisoning **Install/Update** controls.
- **Keep the Plugin Manager route:** disable MO2 sync, remove `ext/mind_poisoning`, and keep or update `ext/CHIM-MindPoisoning`. A sole `ext/mind_poisoning` folder from a 0.1.14-or-newer manager install can remain valid; do not rename it just to match the newer folder name.
- **For a 0.1.13-or-older manager migration:** after backup and disabling MO2 sync, either remove the old `ext/mind_poisoning` code folder before installing with the manager, or first bridge through the old CHIM-Plugins route to 0.1.14 or newer. The bridge is optional, not a prerequisite for the clean-up route.

Removing or disabling MO2 stops future sync; it does not uninstall an existing server folder. Removing extension code does not remove affinity, ledger, or history from CHIM's database. See the [deployment and migration guide](../docs/deployment-migration.md) for the full procedure.
