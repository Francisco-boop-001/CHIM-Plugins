# Mind Poisoning

Mind Poisoning is a CHIM server plugin. It lets a listener's opinion of one named person shift a little after hearing another NPC praise or slander them. The listener can doubt the speaker or change nothing. A companion can also opt into actor-owned solo reflection from an exact registered NPC line ACK. Gossip remains gossip: this does not establish shared world truth or change Skyrim relationship ranks.

**Hypothetical example, not runtime evidence:** Aela tells Lydia that Farkas betrayed the group. Lydia might become slightly less fond of Farkas, remain unconvinced, or change nothing. The plugin does not decide that the accusation is true or change Lydia's affinity toward Aela.

## Relationship-type behavior in v0.1.20 — PRE-ALPHA

Version 0.1.20 adds an optional single CHIM relationship-type change to the existing judgment on already-eligible ordinary NPC gossip, Player-origin input, NPC acknowledgements and overhearing, and registered solo reflection. Isolated fixture checks passed. It uses the existing model call and eligibility gates; it does not add simultaneous labels or change Skyrim's vanilla relationship ranks.

The default is to keep the current type. A change needs clear lasting grounds and exact evidence. Existing custom types are preserved. A current `romantic`, `familial`, or `professional` type cannot be replaced by a temporary reaction type: `jealous`, `protective`, `suspicious`, `fearful`, `obsessed`, `awed`, `contempt`, `pitying`, `grateful`, `curious`, `dismissive`, or `admirer`. In that protected case, the type stays while an otherwise valid affinity change may still apply. A type-only change with zero affinity delta is valid and uses the existing atomic persistence, lock, and replay safeguards.

The relationship-type behavior has isolated fixture coverage only, with no live database, provider, or gameplay verification. The standalone dashboard helper correction also has isolated fixture coverage and no installed-runtime proof. v0.1.20 remains PRE-ALPHA.

## Requirements

- Test in a separate MO2 game profile and an isolated CHIM server/database. A separate MO2 profile alone does not isolate server data.
- CHIM itself works without Playthrough Saves. In v0.1.10, zero active profiles use an explicit `unprofiled` scope shared by the server database; exactly one active profile retains numeric isolation. Multiple, invalid, or ambiguous profile states skip evaluation. A disposable Skyrim save alone does not isolate this database-backed state.
- With CHIM auto-switch Off, there is no reliable unique Skyrim save ID. Source correlation and deduplication remain database-scoped; loading another game save without switching the database or profile does not automatically isolate its events.
- CHIM global relationship processing must be enabled. Passive acknowledgements may be processed only while interaction is On and the request generation is current; Off and stale generations remain blocked.
- `NEVER_CLEAR_RELATIONSHIP_DATA` must be `false`.
- `RELLLM_CONNECTOR` must identify a configured `openrouterjson` or `openrouterjsoncached` connector.
- Locked listener profiles and manual relationship locks are skipped.

The model call is synchronous and can delay the `_speech` acknowledgement. Its 12-second I/O timeout is not a hard wall-clock deadline.

The NPC-origin `_speech` path binds acknowledgements to one chat event by `utt_` ID, with matching speaker, listener, explicit non-broadcast target, and playthrough. The model uses the speech text reported by the client ACK; this is a client report, not independent proof of audio playback. No fuzzy text or event-tail matching selects the event. Aborted, unmatched, ambiguous, duplicate, broadcast, and Player-listener ACKs are skipped.

Published v0.1.17 rejected a Player-subject ACK before the model call when legacy Player aliases were ambiguous; NPC-only ACK events remained eligible. The v0.1.18 candidate reads the CHIM-canonical Player edge in preflight, prompt context, dashboard, and locked persistence. A nonzero Player-subject update consolidates legacy aliases to `Player` within the same locked transaction; Player-speaker-only and NPC-only changes do not rewrite them. At opinion-owner stored-data boundaries, a missing `relationships` property or the exact empty PHP array `[]` is an empty map; explicit `null`, nonempty arrays, and other malformed map shapes fail closed. CHIM's pinned core normalizer selects the canonical Player value, and a normalizer failure prevents model work. v0.1.18 also refuses the reserved `explicit_disable_rechat` sentinel as an addressed or overhearer NPC, even when a catalog row has the same name. See the [release notes](../distribution/mind_poisoning-v0.1.18.md) for verification limits.

The Player-origin input path, introduced in v0.1.7 and present in v0.1.10, accepts `inputtext`, `inputtext_s`, `ginputtext`, and `ginputtext_s`. It correlates the post-insert eventlog snapshot by the exact source tuple and uses `input_<positive rowid>` as its event key. One route-selected listener is the addressee; names in `source_people` may also include bystanders. Narrator, broadcast/everyone, ambiguous route, and uncertain identity cases are skipped. For Player-origin gossip, the Player and listener are excluded as subjects; only other explicitly named known NPCs are considered. This client-reported input text is not an audio ACK or proof of playback.

### Solo reflection in v0.1.14

The namespaced API declares `\ChimMindPoisoning\MIND_POISONING_REFLECTION_API_VERSION = 1`; a compatible companion must check for version 1. The companion API keeps the social roles straight: A talking to B about C evaluates B's opinion of C on the ordinary pair route; a separately registered solo reflection evaluates A's opinion of C. It uses only a private exact registration for A's emitted line plus the matching native `_speech` ACK, event, actor, utterance and explicit rechat sentinel. It never invents a listener or turns A into A's own audience.

The evidence basis uses A's profile and up to eight earlier spoken utterances that identify A as a participant; affinity and prior reflection output are excluded. Up to 32 subject tokens are retained for the current basis outside the rolling event ledger, even when a judgment is zero, so unchanged evidence is skipped. A changed basis may be evaluated again. Registration, request generation, playthrough/configuration scope, pause and persistence guards are rechecked; logs show reflection provenance and opinion owner without the speech, subtitle digest or basis fingerprint.

The extension runs before CHIM updates the current delivery state, so the matched source can be `emitted` or `spoken`; `aborted` is rejected. A matching native ACK signals a correlated line attempt, not audible playback. Fixtures cover fake-store and isolated-registry behavior only. A separate retained-log review includes confirmed solo-reflection decisions and correlated persistence; it does not establish general provider reliability, all installed companion ordering, or audible playback.

Mind Poisoning by itself does not trigger a solo reflection request. A compatible companion must register the actor's exact emitted line and call the API from its matching `_speech` ACK. With a valid opinion change, the dashboard attributes it to the actor; a zero decision or safe skip is not a gameplay change. **Hypothetical, not runtime evidence:** if A tells B that C betrayed them, B may revise B's opinion of C; if A reflects on C, only A's opinion of C is eligible. The allegation remains an allegation—this is gossip, not a Skyrim court ruling.

**v0.1.11 changes (not present in v0.1.10):** Player gossip is eligible only in effective execution modes `STANDARD`, `WHISPER`, or `CLOSE`. Other or unknown modes are skipped at info level with reason `player-input-not-speech`; injected context alone does not count as Player speech.

Names are first found by case-insensitive whole-word matching, so an NPC named May can appear as a candidate when the transcript uses “may” as an ordinary word. In v0.1.4, the existing model call must decide whether each candidate refers to a person; ordinary-word or uncertain uses should return `subject_mentioned=false` with zero delta. Missing or non-boolean mention decisions and false with a nonzero delta are rejected before persistence. This is model-based semantic judgment, not guaranteed entity recognition, so the model can still misclassify a mention. Lowercase names remain eligible and are not filtered by capitalization alone. False lexical candidates still count toward the cap of 8 subjects and may be sent in the same model call.

Each affinity change is between -5 and +5; affinity remains between -100 and +100. A zero change is valid. The prompt can include up to 8 relevant prior events from the same listener and playthrough, with up to 8 subject judgments per event. This bounded, untrusted context is not a cooldown or guaranteed repetition detector, so repeated claims can still influence affinity again. Committed decisions, including zero, retain full NPC/history snapshots.

## Install v0.1.20 PRE-ALPHA through MO2 (recommended)

Mind Poisoning is a CHIM server extension, not a Skyrim ESP. The recommended MO2 ZIP is a normal file-sync mod, not a game plugin. Use a separate MO2 profile and an isolated CHIM server/database for testing; a separate save or profile alone does not isolate server data.

Keep only one enabled Mind Poisoning package version. Disable or remove older MO2/file-sync copies before installing this ZIP or switching to a CHIM Plugin Manager/server TAR route. An older carried package may supersede a manager-installed version on load; behavior in the installed client is unverified.

1. In MO2, install the [v0.1.20 plain ZIP](https://github.com/Francisco-boop-001/CHIM-MindPoisoning/releases/download/mind_poisoning-v0.1.20/mind_poisoning-0.1.20-mo2.zip) as a normal mod and enable it. Keep `CHIM` directly under the MO2 data root. The ZIP already contains `CHIM/server-plugins/mind_poisoning/0.1.20.dwpkg`; do not download, unpack, or insert another DWPkg.
2. Connect to CHIM and ensure **Automatic Game Plugin Sync** is enabled. Then launch Skyrim through MO2 and load a save. Loading a save is CHIM's documented sync trigger; confirm the result in the next step.
3. On CHIM's **Server Plugins** page, open **Automatic Game Plugin Sync** and choose **Refresh Status**. Confirm `mind_poisoning` version `0.1.20` is installed. Then open CHIM Plugin Manager → **Plugin Page**. See the [dashboard guide](dashboard.md) for access assumptions and limits.

The v0.1.20 ZIP's root `meta.ini` supplies MO2 version and source metadata. It does not alter the DWPkg, guarantee that MO2's Skyrim content warning is gone, or prove a server install. MO2's red “The content of <data> does not look valid” warning is a separate game-content classification check: this mod carries CHIM data rather than recognized Skyrim files. If **Ignore** or **Continue** is offered and lets you finish, it only proceeds past that MO2 check. It does not show that CHIM read the package. A CHIM “couldn't read” or sync error is separate and remains undiagnosed here. Report whatever is available: the exact error text if visible, DWPkg filename/path, plugin version, CHIM/client revisions, and relevant sanitized `SERVER_PLUGIN_SYNC` log lines. If the exact text or logs are unavailable, say so; do not infer a cause or treat **Ignore** as a fix. Remove credentials and private paths before sharing logs.
