# Preserve-on-reload compatibility

**Status: implemented in the 0.1.25 candidate source; focused Windows fixtures and a bounded disposable PostgreSQL compatibility fixture pass.** The immutable Mind Poisoning 0.1.24 release still stops when CHIM's effective `NEVER_CLEAR_RELATIONSHIP_DATA` value is true. The native fixture used pinned CHIM 3.5.1 source revision `57f292415b008cfaf1a4531f0654d2563362ce70`; it does not establish a full ACK runtime request, provider, installed server, or gameplay result. Package/source-export, clean-tag, and publication-byte gates are reported separately.

## Reading `restore-policy`

For a historical `restore-policy` row, check **Outcome**, `stage`, and `model_outcome` together. `stage=preflight` with `model_outcome=not_called` means that request stopped before model work; a persistence-stage refusal can occur after model work. Newer reason codes distinguish an expired source, a completed scope baseline, a changed INIT boundary or setting, and other safety failures. A log records what a check observed; it does not reveal the current value, its UI location, or its default. Reinstalling the plugin or changing providers does not resolve this policy.

CHIM preserve mode can keep current relationship values while restoring older plugin history, including Mind Poisoning's duplicate-prevention ledger. Do not turn off a protection setting just to clear a reason. Before a deliberate setting or restore change, back up the CHIM database and configuration, drain pending work, quiesce the request pool, make the change, then restart the workers; changing policy during in-flight work can discard that request.

## Accepted compatibility contract

With effective preserve mode enabled, the 0.1.25 candidate source does the following:

- It requires covered ACK, Player-input, and reflection source event row IDs to be newer than the latest actual `init` row in `eventlog`. It captures that boundary before model work and rechecks it under CHIM's `MAIN` serialization barrier before persistence. For reflection v2, it checks every registered reply output-line source ID; historical evidence/context rows are not the reply's source-ID list. Older Mind Poisoning judgments are excluded from prior-judgment prompt context, while current relationship notes and types remain.
- If an owner's nonempty ledger has a different playthrough scope, it writes a new-work baseline before model work. The baseline advances its floor to the current maximum event row ID, clears imported plugin event/judgment/reflection context, leaves loaded relationship values unchanged, and skips the triggering event. Already-inserted pending sources can therefore expire at this baseline; only later event IDs are eligible.
- If the loaded namespace already matches the active scope, it does not replace that namespace with a scope baseline; the existing exact-event and bounded-floor checks apply to the history CHIM actually loaded. This is not a claim that every newest MP receipt survives CHIM's restore: native proof showed relationship affinity 13 retained while MP history rewound to an older floor and receipt. The independent INIT source-ID fence is what expires pre-load source rows. The disabled-policy path remains unchanged. Missing or malformed required state, unresolved scope, an unsafe INIT path, or lock failure stops safely. A final MAIN-lock failure can occur after model work, but prevents persistence.

This is source-ID replay protection, not semantic deduplication. The same claim under a newly inserted ordinary event ID remains new input; reflection also retains its existing unchanged-basis guard, so a newer line does not guarantee a new reflection evaluation. The contract does not promise once-per-fact behavior, a nonzero affinity change, or provider success.

| Effective CHIM policy | Unlocked NPCs with eligible history | NPCs without eligible history | Candidate behavior |
| --- | --- | --- | --- |
| `NEVER_CLEAR_RELATIONSHIP_DATA=false` | CHIM restores relationship values, types, notes, and the MP namespace from its selected history. | This restore path does not rewrite the NPC row. | Existing restore/replay behavior; no new preserve-mode fence or baseline. |
| `NEVER_CLEAR_RELATIONSHIP_DATA=true` | CHIM retains current relationship values, types, and notes while restoring the MP namespace from selected history, which can be older. | This restore path does not rewrite the NPC row. | Expire covered pre-INIT source rows and filter old MP judgments from prompt context. For a mismatched nonempty scope, write a fresh baseline and skip that event. A matching loaded scope is not reset by the plugin, but its ledger may already be older from CHIM's restore. |

The setting's exact user-facing label, UI location, and default have not been verified here. Focused Windows fixtures cover ordinary ACK, Player input, reflection v2, overhearing boundary/baseline behavior, policy changes, and PostgreSQL-style string NPC IDs. The disposable native fixture exercised pinned INIT pruning/restoration, production store boundaries, synthetic persistence, exact retry, the ordered store/INIT barrier, scope baseline, rollback, and a dump/restore projection. It did not exercise a full ACK request or general concurrent-ACK/crash behavior, and made no model/provider call. It does not verify an installed server or gameplay.
