## Existing-install migration

### Historical migration from Mind Poisoning 0.1.13

The old 0.1.13 channel used a `<version>` package URL under `CHIM-Plugins`. Its version-matched 0.1.14 compatibility release was the migration bridge to the dedicated deployment repository. That bridge's package manifest identifies `Francisco-boop-001/CHIM-MindPoisoning`; verify the installed version and `git_repo` before relying on later updates through the dedicated repository's explicit manifest channel. The old 0.1.13 tag and assets remain unchanged. New MO2 installs use the current MO2 ZIP and do not need this bridge.

### Private Conversation 0.1.4 and 0.1.5

Both published manifests point to literal, version-specific `CHIM-Plugins` package assets: [0.1.4](https://github.com/Francisco-boop-001/CHIM-Plugins/releases/tag/private_conversation-v0.1.4) and [0.1.5](https://github.com/Francisco-boop-001/CHIM-Plugins/releases/tag/private_conversation-v0.1.5). In particular, 0.1.5 does not substitute a future version into its package URL, so its Plugin Manager update button cannot migrate itself to the new repository. Keep the 0.1.4 and 0.1.5 assets unchanged. Replace the existing PCV server package once with the versioned 0.1.21 `.dwpkg` or the legacy manifest/channel route configured for `Francisco-boop-001/CHIM-PrivateConversation`. For file sync or that version-substituted channel, verify the installed manifest reports `version=0.1.21` and `git_repo=Francisco-boop-001/CHIM-PrivateConversation`. For Plugin Manager topic discovery, expect the generated manifest to report `version=private_conversation-v0.1.21` and `release_tag=private_conversation-v0.1.21`; these are distinct installation identities. The standalone 0.1.14 manifest reads the dedicated repository's `main/server/manifest.json` and uses a version-substituted release URL, so later releases can update through that channel after the versioned assets and `main` manifest are advanced. The [0.1.8 `CHIM-Plugins` bridge](https://github.com/Francisco-boop-001/CHIM-Plugins/releases/tag/private_conversation-v0.1.8) remains a historical versioned download, not a way for the old 0.1.4/0.1.5 literal URLs to self-migrate.

### Private Conversation 0.1.8 state migration

Before updating, quiesce old PCV requests and keep HTTP access restricted through the first state resolution. Migration runs on first state access, not installation. The default state path uses a validated operating-system temporary root separate from `PCV_LOG_DIR`; the operating system may clean it. A valid legacy state directory moves only by atomic `rename()` when the destination is absent and both paths share a filesystem. Migration fails closed on corrupt, unsafe, unknown or conflicting data and on `EXDEV`; the legacy source remains in place, with no copy, merge or reset.

The private path depends on the effective PHP worker UID, canonical extension path, and temporary-root namespace. A CLI temp directory or matching UID does not establish the HTTP worker's path; separate namespaces such as systemd `PrivateTmp` can resolve different roots. Until migration succeeds, legacy state may remain HTTP-readable if server overrides are ignored, so the package is not an independent access boundary. This source and isolated-fixture evidence does not establish installed CHIM or PHP-FPM behavior.

For either plugin, use one server-package route at a time. Disable or remove older enabled MO2/file-sync copies before switching to Plugin Manager; do not stack versions. A release page or Plugin Manager listing alone does not prove which code is installed.

## Plugin Manager routes and verification limits

The topic-discovery route uses the GitHub `chim-plugin` topic and stable release asset name `chim-plugin.tar.gz`; drafts and prereleases are ignored. Mind Poisoning 0.1.21 is configured as a standard release, with the candidate label kept in its description and package metadata. Newer core source review shows a clean install uses `ext/CHIM-MindPoisoning`; when it recognizes an existing package with the same valid `git_repo`, it uses that folder in place rather than renaming it. An unknown-source legacy folder may remain. This source review is not a live migration guarantee: inspect the manager result and stop if duplicate or unknown-source folders remain; do not stack copies or delete a folder blindly. The pinned `cf5030f` core does not contain topic discovery. Existing manifest/channel clients remain a separate route. A release page, asset, or checksum alone does not prove a package is installed or synchronized.

Private Conversation 0.1.21 is a normal published BETA release so CHIM discovery can see its flat [`chim-plugin.tar.gz`](https://github.com/Francisco-boop-001/CHIM-PrivateConversation/releases/download/private_conversation-v0.1.21/chim-plugin.tar.gz); the required `prerelease=false` flag is a discovery filter, while BETA is the release maturity label. In CHIM, use **Server Plugins** → **Refresh Plugins** → **Install Plugin** on the PCV row; for updates, use **Update <channel label>**, confirm in the installer, then return to **Plugin Page**. Fresh repository-slug installs normally resolve to `ext/CHIM-PrivateConversation`; recognized updates may preserve `ext/private_conversation`, so use the generated page URL. The legacy candidate-manifest `private_conversation.tar.gz` remains wrapped and is consumed by CHIM’s installer with its configured one-directory strip; do not unpack it manually. The MO2 ZIP embeds the DWPkg. Choose one route per server.

If an inactive 0.1.21 Plugin Page returns HTTP 409, use its named owner path and send END there before switching or removing a duplicate. The 0.1.20 duplicate fixture confirms that a single unguarded 0.1.19 copy remains owner while 0.1.20 is present; the 0.1.21 runtime payload matches that tested code. Two unguarded 0.1.19 copies can still collide even with 0.1.21 present. Keep one active source. PCV does not automatically migrate runtime state between install paths. See the [0.1.21 operator evidence and limits](https://github.com/Francisco-boop-001/CHIM-PrivateConversation/blob/private_conversation-v0.1.21/docs/operator-acceptance.md).

PCV checks for a compatible Mind Poisoning API already loaded by CHIM rather than requiring one fixed version. Mind Poisoning 0.1.21 exposes the compatible namespaced API for fresh repository-slug installs; legacy 0.1.16 remains a known released option with reply API v2. This is source-level compatibility guidance, not proof that either version is installed or loaded in a live target.

The historical cross-plugin check remains source-bound: the immutable Mind Poisoning 0.1.14 tag retains its matching Private Conversation 0.1.6 snapshot and its evaluator-to-observer-to-importer fixture; this PCV bridge does not retag or rebuild MP 0.1.14. The standalone PCV 0.1.15 `reflection_registry_check.php` requires matched MP 0.1.16 evaluator/API fixtures. The MP observer fixture dynamically loads the embedded snapshot: its recorded five-case pass used PCV 0.1.12 before this pin, and no 0.1.15 run is claimed. The immutable published MP 0.1.16 tag retains PCV 0.1.8 at that path. A PCV-only export cannot provide MP source. Runtime packages include only each plugin's explicit server-file allowlist, not the other plugin or tests.

These repository, manifest, fixture, and package checks do not establish clean live installation, proxy/authentication topology, live database/provider behavior, or Skyrim speech/audio delivery. Mind Poisoning 0.1.21 is a BETA CANDIDATE; the compatibility reference is unchanged and is not an installation pin.
