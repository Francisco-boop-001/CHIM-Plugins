## Behavior

The v0.1.6 hook evaluates `_speech` acknowledgements. It binds to exactly one chat event by `utt_` ID and checks speaker, listener, explicit non-broadcast target, and active playthrough. The text used for subject extraction and judgment is the client-reported ACK speech. That is CHIM's acknowledged text report, not independent proof of audio playback. The logged event remains the identity and persistence anchor; no fuzzy text or tail matching selects an event. This behavior remains in v0.1.7.

Passive ACKs may be evaluated while the interaction switch is On and the request generation is current. Off and stale generations remain blocked, including a switch during the synchronous model request. Aborted, malformed, duplicate, unmatched, stale, broadcast, ambiguous, and Player-listener events are skipped. If the current event names the Player as a subject, ambiguous legacy Player relationship aliases are rejected before a paid model request and rechecked before commit; NPC-only events remain eligible.

The model evaluates explicitly named known NPCs or Player, up to 8 subjects and 12,000 bytes of speech. It returns a signed delta from -5 through +5, including zero; resulting affinity stays within -100 and +100. The update changes only the listener-to-subject affinity edge. It does not edit Skyrim relationship ranks or establish hearsay as shared world truth.

The prompt may include at most the last 8 relevant prior events for the same listener and playthrough, with up to 8 subject judgments per event. These are untrusted, bounded model notes, not verified claims or a cooldown. Repetition guidance cannot guarantee that a repeated claim will not change affinity again.

### Solo and full-reply reflection APIs (published v0.1.16)

`server/reflection.php` declares `\ChimMindPoisoning\MIND_POISONING_REFLECTION_API_VERSION = 1` and exposes `mindPoisoningEvaluateReflection(array $registration, array $gameRequest, StoreDb $store, callable $revalidate, ?callable $requestModel = null, ?RequestLog $requestLog = null): string` for a companion plugin. It is side-effect-free on load and is not called by Mind Poisoning's ordinary `prerequest.php`; the companion must check the exact version and invoke the API from the matching `_speech` ACK using a private server-side registration for the exact event, utterance, actor, playthrough, configuration, explicit `explicit_disable_rechat` target, and SHA-256 of the exact emitted subtitle. The API rechecks that registration before model work and during persistence, and reuses the existing store, parser, model safeguards, and transaction path.

Reflection uses `source_kind=reflection`: the speaker actor owns the opinion and its relationship row (`opinion_owner_id=actor_id`, `listener_id=null`). It does not create an actor-as-listener ACK. In the pair route, A talking to B about C evaluates B's opinion of C; solo reflection evaluates A's own opinion of C from A's exact registered line ACK. The bounded evidence basis uses the actor profile and up to eight earlier `spoken` actor-known utterances, excludes affinity and prior reflection output, and records up to 32 subject tokens for the current basis separately from the 128-event rolling ledger. Zero-change results also record the basis, so unchanged evidence is not bought again forever; a new evidence basis can permit another evaluation.

The extension prerequest runs before core `_speech` updates its delivery state, so the exact current source may be `emitted` or `spoken`; `aborted` is rejected. A matching native ACK establishes a server-side line attempt, not proof of audible playback. The companion must retain the private registration; missing, stale, mismatched, or consumed registrations skip safely. The existing generation, pause, scope, actor-eligibility, provider, and transaction safeguards still apply. Reflection diagnostics expose provenance and the opinion owner but omit the dialogue, subtitle digest, and basis fingerprint. Focused fake-store and isolated-registry fixtures cover this route; live database, provider, installed companion ordering, and audio delivery remain unverified. The model is allowed to be unconvinced. We have enough omniscient narrators already.

Mind Poisoning 0.1.15 introduced the opt-in v2 full-reply capability, `MIND_POISONING_REFLECTION_REPLY_API_VERSION = 2`, alongside the unchanged v1 API. Private Conversation 0.1.15 retains its exact v1 requirement and conditionally calls v2 when the capability, evaluator, source helpers and proven reply grouping are available; otherwise it registers only the final line through v1. See the [integration API](../docs/integration-api.md) for the registration, revalidation, replay, and diagnostic contract. The final ACK and emitted source rows show a line-attempt sequence, not that every line was heard or played.

The published Mind Poisoning 0.1.15 package accepts 1–8 reply lines; the published 0.1.16 release accepts 1–24. The eight-subject limit and joined-text caps of 2,000 Unicode code points and 8,000 bytes remain unchanged.

### NPC ACK overhearing (v0.1.17)

The namespaced capability marker is `\ChimMindPoisoning\MIND_POISONING_NPC_ACK_OVERHEARING_API_VERSION = 1`. Overhearing is off by default with `mind_poisoning_overhearing_enabled=false`; an administrator enables it through CHIM's supported `chimSetGeneralSetting` helper in the administrator-managed bootstrap. Mind Poisoning adds no setting-write endpoint.

One eligible NPC `_speech` acknowledgement can evaluate its addressed listener plus up to four additional eligible NPCs from that exact event's `eventlog.people` roster in one model call (maximum 4,096 tokens; the ordinary addressed-only call remains capped at 1,024). If more than four eligible extras are present, the extras are skipped and the direct addressed-listener path continues. The roster establishes event membership, not playback or Private Conversation scene participation. Sentinel-targeted PCV 0.1.15 wrap-up lines normally skip the witness batch when no NPC catalog row resolves; see the [integration API](../docs/integration-api.md) for the released MP 0.1.17 catalog-collision edge and unreleased-guard status; if SHARMAT pins a member, eligibility follows the actual source, ACK and ordinary MP gates. Scene-card text is prompt context, not event evidence.

Each listener persists independently, so partial outcomes are possible. Replay checks run sequentially and do not reserve provider work across concurrent acknowledgements. Per-listener records carry `listener_role` (`addressed` or `overheard`), `addressed_listener_id`, and `batch_id`. Focused fixtures pass; real provider, database, native setting, installation and gameplay behavior remain unverified. See the [0.1.17 integration API notes](../docs/integration-api.md#npc-ack-overhearing-api-v0-1-17).

Mind Poisoning alone does not start solo reflection. A compatible companion must register the exact actor output and invoke this API on its matching native ACK. If the unchanged-evidence, identity, scope and runtime gates pass, the validated opinion can appear in the dashboard; a zero decision is still a completed evaluation, and a skipped or failed result is not a gameplay change. **Hypothetical, not runtime evidence:** if A tells B that C betrayed them, the pair route evaluates B's view of C. If A reflects on C through a compatible companion, the solo route evaluates A's view of C. Neither makes the claim true, and A is not made to listen to A.

The ordinary pair and Player-input hooks also require global relationship processing enabled and `NEVER_CLEAR_RELATIONSHIP_DATA=false`. They skip nonzero `lock_profile` and manual relationship locks; `relationships_locked` follows PHP `!empty` semantics. Only the configured `openrouterjson` or `openrouterjsoncached` connector is supported. The plugin selects no alternate connector, though the provider may use its own fallback. Calls are synchronous with a 12-second I/O timeout and 1024-token limit; the timeout is not a hard wall-clock deadline.

### Operator pause (v0.1.10)

Introduced in v0.1.9 and retained in v0.1.10, this server-side operator control uses `data/mind_poisoning.json`; it is not a dashboard setting. Run from the CHIM root to pause; use `{"enabled":true}` instead to resume:

```sh
mkdir -p -m 0755 data
tmp=$(mktemp data/.mind_poisoning.XXXXXX) &&
printf '%s\n' '{"enabled":false}' > "$tmp" &&
chmod 0644 -- "$tmp" &&
mv -f -- "$tmp" data/mind_poisoning.json
```

The PHP worker must be able to traverse `data/` and read the file. Missing `data/` or a missing control file keeps the plugin enabled; malformed or unreadable control state fails closed. The reader accepts only the literal `enabled` key with one boolean value, rejects duplicate keys, and allows standard JSON whitespace. The dashboard stays read-only. See the source-checkout [developer guide](../docs/development.md) for full path, format, and timing rules.

## Persistence and limits

The Player-input hook matches the post-insert eventlog snapshot by the exact supported source tuple and stores the positive row ID as `input_<rowid>` in the existing event correlation slot. Bystanders in `source_people` are not additional listeners; a narrator, broadcast/everyone mode, ambiguous route, or uncertain identity is skipped. The model may select named NPCs as subjects but does not treat the Player as a subject when the Player is the speaker. This route is not evidence of delivered or heard audio.

Persistence uses the guarded `sql::$link` compatibility shim and retains one native connection for the transaction, advisory lock, row lock, relationship update, plugin ledger, and full NPC/history snapshot. Committed zero decisions also write the ledger and snapshot without changing affinity. Failed writes or snapshot verification roll back the transaction. The bounded ledger holds up to 128 event IDs and advances a numeric floor; events at or below the floor are skipped, including unseen or out-of-order IDs.

Version 0.1.10 retains the cap of 1 second per transaction lock wait and 3 seconds per statement, preserving any stricter positive inherited value. These settings are transaction-local. They bound individual waits/statements, not the total transaction or request.

The candidate has not been verified with live PostgreSQL writes or concurrency, a live provider, or in-game playback/save-load. Some upstream relationship writers do not take the shared advisory lock and can overwrite a later update. Core restore with `NEVER_CLEAR_RELATIONSHIP_DATA=true` preserves scores but rewinds plugin ledger state, so this mode disables the hook. Removing the plugin stops future evaluations; it does not undo stored affinity or prior snapshots.

## Structured request logging

Request summaries go to CHIM's `log/chim.log` through the native `Logger`; if that class is not already loaded, they use PHP `error_log()`. There is no new log file or plugin-level CHIM logger setting. The native logger's configured threshold still applies, and warning/error records are duplicated to PHP/Apache error logging. CHIM's prefix surrounds each one-line JSON payload.

Info summaries are the default. For diagnostics, set `MIND_POISONING_LOG_LEVEL=debug` in the PHP worker's service environment and restart/reload that worker; a shell-only export does not affect an existing web worker. Correlate the per-request `request_id` with the validated `utt_` or `input_<rowid>` key when available. The helper filters to bounded identifiers, result codes, measurements, and numeric/token relationship details. It has no dedicated raw-speech, name, prompt, or credential fields, and drops arbitrary exception strings. Debug-only `model_reason` is untrusted and capped at 240 UTF-8 bytes, so it may still contain names or a limited game/model excerpt.

Version 0.1.10 assigns fixed `payload_*` reason codes to malformed or oversized `_speech` payloads while keeping the request outcome skipped and warning-level. It never logs the rejected payload or speech. Released v0.1.9 logged absent `utterance_id` as warning `payload_utterance_id_missing`; v0.1.10 skips only otherwise-valid absent or empty/whitespace-only string IDs as info `untracked-speech` / `utterance_id_absent`. Wrong-type and malformed IDs remain warning-level rejections. See the source-checkout developer guide for the attributed historical analysis and code list.

Persistence summaries include `commit_state`: `not_attempted` means COMMIT was not sent, `confirmed` means the store reported success, and `unconfirmed` means COMMIT was attempted without reliable confirmation. `committed: true` means confirmed; `false` does not prove no database change if the COMMIT acknowledgement was lost. `cleanup_failed` is separate because cleanup may fail after a confirmed commit.

Logging is best effort: an early process exit may leave no finish summary, and a sink failure drops the record instead of disrupting the ACK. In the inspected CHIM source, the UI truncates `.log` files above 25 MiB when its index runs; it does not archive them. The installed Apache rotation rule does not cover CHIM's log directory.

Version 0.1.11 normalizes ACK IDs with core-compatible `trim()` and permits Player gossip only in effective `STANDARD`, `WHISPER`, or `CLOSE` mode. Other modes skip as info `player-input-not-speech`. Focused fixtures passed; these changes await live gameplay verification.
